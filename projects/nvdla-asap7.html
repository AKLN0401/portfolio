NVIDIA NVDLA 7 nm Full-Chip Implementation: Low-Power, PPA-Optimized, DFT

NVIDIA’s open-source deep-learning accelerator, implemented on the open ASAP7 7 nm predictive PDK, so the timing numbers and cell geometry here can be shown as they are.

Target 1.0 ns at the fast corner with LVT, RVT and SLVT cells, kit files kept read-only. All five partitions are synthesized and meet 1.0 ns with zero violating paths: 7.3 M cells and 1.54 M scan flops on 641 chains. Place-and-route is under way, starting with partition C.

How NVDLA works

ARCHITECTURE

NVDLA (NVIDIA Deep Learning Accelerator) is a fixed-function inference engine that NVIDIA open-sourced in 2017. A host CPU programs it through a register interface (CSB), points it at feature maps and weights in memory, and the hardware runs a layer (convolution, activation, pooling, normalization) without the CPU touching the data.

The convolution core does most of the work. CDMA streams feature-map data and weights from memory into the on-chip convolution buffer (CBUF). The sequencer (CSC) reads them back in the order the math needs, decompressing sparse weights on the way, and feeds the MAC array (CMAC), split into two identical halves. CACC sums partial results across channels.

Results then flow through the post-processing pipeline: SDP applies per-element operations (bias, batch norm, ReLU/PReLU, element-wise add), PDP does max/min/average pooling, and CDP does cross-channel local response normalization using lookup tables for exp/log. BDMA and RUBIK copy and reshape tensors between layers.

For physical design, NVDLA is cut into five partitions, synthesized independently here. The colours below show which partition each block lives in, and why partition C (448 SRAM macros for CBUF) and partition O (four LUT engines in CDP) were the hard ones.

Proving the DFT flow

TEST DESIGN

Before running NVDLA, I ran the full synthesis and DFT flow on a small test design. It holds each structure that tends to break scan: Genus and RTL clock gates (one with its test pin tied to 0 in the RTL), async set/reset flops, a flop-based RAM, a negative-edge flop and a synchronous reset.

The key setting: Genus must be told the scan-enable before it inserts clock gates. Otherwise it ties each gate’s test pin to 0, the gates block the shift clock, and the flops behind them drop off their chains.

The popcount path

RTL FIX

Partition C’s worst path came from one structure in the sequencer’s weight decompressor. To find where each surviving weight goes, it computes the prefix popcount of a 128-bit sparsity mask: the number of ones in bits 0..N, for all 128 values of N. The RTL writes these as 128 separate long additions, and synthesis turned them into a ripple chain about 80 gates deep.

No tool setting halves an 80-gate path, so I rebuilt it as a parallel prefix: an 8-bit count inside each of 16 groups, then a 4-level Sklansky tree over the group totals. Same outputs, same clock cycle. I checked it against a bit-by-bit reference in Xcelium over 20,000 random and corner-case vectors (zero mismatches). The rewritten module is part of the RTL used for the current runs.

Inside 7 nm

ASAP7 GEOMETRY

ASAP7 models a 7 nm FinFET process: fins, gate, and a middle-of-line contact stack (LIG, LISD, SDT) between the transistors and metal 1. Standard cells are 0.27 µm tall; a row as wide as a human hair (about 70 µm) fits roughly 50 scan flip-flops.

Scan on the stock kit

Stock ASAP7 scan flops lack the test_cell description synthesis needs, and the kit stays read-only. So synthesis maps to plain flops, then my script swaps each one for the kit’s own SDFH/SDFL scan flop and stitches 128 chains. The kit has no scan flop with async set/reset, so those flops get a scan mux in front of D, built from the kit’s AO22 cell, so they go on the chains too.

Hidden SRAM pins

The kit SRAM has five pins, sdel[4:0], that appear only in its LEF, not in its Verilog or Liberty. I traced them through the kit GDS: they select the delay from word-line enable to sense-amp enable. They are tied to 00000, the longest delay and the most read margin, with one tie cell per macro.

A unit bug in the kit SRAM

The kit SRAM’s timing library has a unit error: its header declares nanoseconds and picofarads, but the clock-to-output tables hold picosecond and femtofarad numbers, so the tool read a 151 ns read delay. Since the kit stays read-only, the fix is a project-side copy with only those 8 tables rescaled (read delay now 0.15–0.60 ns), documented next to the original. It will be in the final report as a kit issue.

Three threshold voltages

Synthesis and place-and-route use the kit’s fast-corner libraries (0.77 V, 0 °C) in three Vt flavours: SLVT and LVT where a path needs speed, RVT everywhere else to hold leakage down. All five partitions together leak about 2.3 mW in synthesis.

Which RAMs become SRAM

NVDLA has 34 RAM types. The 23 with 128 words or fewer are flop arrays; the 11 deeper ones are built from the kit’s single-port SRAM banks, two banks per two-port RAM. I wrote each model and checked it against NVIDIA’s own RAM model in simulation, cycle by cycle: 0 mismatches for all 34. A copy with a planted bug failed the same test with 6,510 mismatches, so the test does catch bugs.

A via rule the router misreads

The kit’s via-enclosure rule for V3 and V5 lists two overhang values without saying which is the end and which the side. Innovus guesses and gets it backwards, so it flags vias that meet the ASAP7 design manual (11 nm on two opposite sides). Making the via pads bigger traded those flags for about 24k other errors. Instead, place-and-route reads a project copy of the tech LEF that writes out END and SIDE explicitly, with the manual’s values. The kit file itself is unchanged.

Low power, test and PPA

IMPLEMENTATION

All five partitions share one synthesis script, so each gets the same treatment.

Clock gating

fixed

NVDLA’s own RTL clock gates are imported as real gating cells, and synthesis adds more where flops share an enable. Every gate’s test pin is driven by scan-enable. Gates whose test pin already has logic get scan-enable ORed in, and a check stops the run if any test pin is still tied to a constant.

Scan chains

flow verified

128 chains per partition, stitched after mapping from the kit’s own cells and written out as SCANDEF for place-and-route to reorder. Each new netlist gets two checks before place-and-route: Conformal equivalence against the RTL, and Modus chain tracing plus stuck-at ATPG coverage.

MBIST

inserted in C

Siemens Tessent MemoryBIST, with a memory description I wrote for the kit SRAM bank. Partition C holds all 448 SRAM macros (the CBUF) on 16 controllers, one per bank, driven from an IJTAG port. The other partitions keep their RAMs as flop arrays, which the scan chains test.

PPA optimization

applied

Genus 25.1 at its highest optimization effort, in Cadence’s documented settings. The popcount rewrite above stays in. The clock period and constraints stay fixed: no clock uncertainty and no IO budgets, by design. Misses get fixed in the design or the flow, not by relaxing the target.

Place-and-route plan

FLOORPLAN

Each partition is placed and routed on its own as a hard macro, then the chip is assembled from those blocks. The floorplan is mirror-symmetric: one MAC partition layout is used twice, with MB flipped. Block outlines come from synthesis area; pins sit only on the edges that face the block they connect to, taken from the top-level netlist.

I chose the arrangement by counting every signal between partitions in NVDLA’s top-level netlist. The connections turn out to be almost mirror-symmetric: MA talks to O and P exactly as MB talks to C and A (2,424 and 1,435 bits), and the only large links across the middle are O–C and P–A. Putting the MAC partitions on the outside and O/P, C/A in a 2×2 centre gives every connected pair a shared edge. The blocks span 2.89 × 1.38 mm, all block sizes sit on a 34.56-unit grid shared by every row and track pitch, and the chip-level scan chains pass MA → O → C → MB → A → P, one neighbour to the next.

Partition C goes first because it is the hardest: 448 SRAM macros and 1.45 M cells. Its init checks are clean (all 7,952 pins legal, 0 power-grid DRC, every SRAM’s power and sense-delay pins connected, 129 scan chains traced). In the middle of placement, the main register-to-register group is within 5 ps of 1.0 ns. Numbers get posted here once each stage finishes.

Power grid: the ASAP7 reference recipe (M1/M2 rails, M3–M6 stripes) plus M7 stripes for the chip-level grid to land on. Design-rule signoff is the Innovus checker reaching 0, with the V3/V5 rule read as the design manual defines it (see the via card above).

Next

ROADMAP

  1. Check every netlist

    Conformal equivalence against the RTL (must be 0 non-equivalent points), then Modus chain tracing and stuck-at ATPG coverage per partition.

  2. Verify MBIST on gates

    Simulate the Tessent patterns on C’s gate-level netlist with the SRAMs, including fault injection and one full-address run, and check timing at 1 GHz through the BIST muxes in front of the SRAMs.

  3. Block place-and-route

    C now, then A, M, O and P: init, placement, clock tree, routing and signoff at 1.0 ns, checking the router’s design-rule count at every stage, not just timing. Then each block is exported as a hard macro (LEF + timing library).

  4. Chip assembly and signoff

    Six macros (the MAC partition used twice, mirrored), an M8/M9 power mesh checked for IR drop in Voltus, 128 chip-level scan chains and the MBIST port, then the pad ring. Signoff covers SI-aware timing and an Innovus DRC count of 0. LVS needs the Calibre decks, which are not part of the kit download, so it will be reported as not run.

One-Tile int4 NPU (2x2 MAC Array) for Tiny Tapeout

A 2×2 int4 multiply-accumulate array with 16-bit accumulators, one clock gate per row and a 96-flop scan chain, taken from RTL to a signed-off layout in a single 161 × 112 µm Tiny Tapeout tile. Built for the TTSKY26d shuttle; the demo board's microcontroller drives it over the pins.

2. How it works

The chip is a small matrix-multiply engine without a CPU. A CPU does not fit in one tile: TinyQV alone synthesizes to ~65.6k µm², 3.6× the 17,955 µm² die. The microcontroller on the Tiny Tapeout demo board acts as the host instead: it writes operands into the chip over the pins, tells it to step, and reads the results back.

  1. Write a register. The host puts the address on uio[2:0] and the byte on ui[7:0], then raises the strobe uio[3]. The strobe is synchronized to the chip clock (2 flops) and its rising edge loads the byte (§7).
  2. Load operands. A0 holds two int4 values a[0], a[1] (one column of A), B0 holds b[0], b[1] (one row of B).
  3. Step. A CTRL step (or, in auto mode, any B1 write) opens each enabled row's clock gate for exactly one cycle, and all four PEs add a[i]·b[j] to their accumulator. K steps compute a 2×2 block of C = A·B with inner dimension K (up to 511 without overflow).
  4. Read back. Writing RSEL picks an accumulator and a byte; uo[7:0] then shows that byte. Four reads give the 32-bit sign-extended value.
  5. Sleep between steps. When nothing is stepping, the row clock gates are closed: the 64 accumulator flops and their clock tree get no clock edges (§9).
  6. Test on silicon. test_mode (uio[4]) forces the clocks on and links all 96 flops into one shift register from uio[6] to uio[7], so any internal state can be loaded and read out on the bench (§10).

5. System

The microcontroller writes operand bytes and commands over a small register bus, the chip does all four multiply-accumulates in one clock, and the host reads accumulators back one byte at a time through RSEL.

Figure 5 — Data path (orange), register bus (grey), scan chain (dashed). uio_oe is fixed at 0x80: only uio[7] is an output, driven 0 unless test_mode.

6. Register map

Write-only registers, 3-bit address on uio[2:0]. Operands are signed int4 (−8…7), two per byte.

ID bytes: 4E 22 10 01 = 'N', 2×2 array, 16-bit accumulators, version 1. Reset clears every accumulator and the A/B operand registers.

7. Write protocol

The host's pins are asynchronous to the chip clock. Only the strobe is synchronized (2 flops plus one for edge detect); address and data are sampled directly, which is safe because the host holds them stable while the synchronized edge arrives.

Figure 6 — The synchronized edge fires wr 1–2 clocks after the strobe rises; the register takes the new value on the next edge, 2–3 clocks after the rise. A step or clear requested by that write acts one clock later still, so an auto-step on B1 sees the new B byte.

At 50 MHz one write needs ≥ 120 ns on the chip side — far below what host GPIO code takes, so the host's own speed sets throughput, not the chip clock.

8. MAC array

One step is an outer product: for every enabled row i and every column j, acc[i][j] += a[i] · b[j]. A matrix product C = A·B with inner dimension K is K steps, each loading one column of A and one row of B.

// npu_pe.v — one MAC unit, clocked by its row's gated clock
if (scan_en)    acc <= {acc[ACC_W-2:0], scan_in};
else if (clear) acc <= 0;
else if (step)  acc <= acc + sign_extend(a * b);   // int4 × int4 → 8-bit product

Accumulator width: 16 bit. The largest product is −8·−8 = 64. 16-bit accumulators (max 32,767) take 511 worst-case steps, so a whole 64-input dot product (8×8 digit image) fits in one pass; 12-bit would have allowed only 31 (the host would have to split K). Overflow wraps (two's complement).

9. Clock gating

Each row has one sky130_fd_sc_hd__dlclkp_1 integrated clock gate (wrapper src/dft/clk_gate.v). The latch is transparent while clk is low, so the enable can't glitch the gated clock.

en[i] = (step_q && !scan_en && row_en[i]) || clear_q || !rstn    // functional enable
GATE  = en[i] || test_mode                                     // test mode forces the clock on

A row's accumulators and their clock tree toggle only on the cycle after a step or clear. Between steps the host is busy writing operands for dozens of chip clocks, so the array is idle almost all the time. The cocotb test counts the edges of each row's gated clock: for every ROWEN mask, 3 steps give 3 edges on an enabled row and 0 on a disabled one, and test mode keeps both clocks running.

Power saved: vector-based estimate

To find out what the clock gates buy, the post-PnR netlist was simulated running real workloads, and its switching activity went into the signoff timer's power engine with the routed parasitics. Each workload ran twice with identical bus traffic: once normally, and once with test_mode high, which forces both row clocks on. That second run is the design as it would be without clock gating.

With the gates working, the NPU's power hardly depends on the workload (191 µW idle, 277 µW at the maximum bus rate). What's left is the always-on part: the root of the clock tree and the 34 interface and synchronizer flops. Turning a row off with ROWEN only saves another 17 µW here, because each row's clock is already off about 95% of the time.

Method

  1. Real netlist, real protocol. The post-PnR netlist (the same file the Tiny Tapeout CI builds) is driven through its pins at 50 MHz by a host model that follows the datasheet write protocol, streaming int4 matrix-multiply steps (A0, B0, CTRL step) with fixed-seed random operands.
  2. Same traffic, gating defeated. The baseline repeats the identical stimulus with test_mode high. That forces both clock gates open, while the MAC units still hold through their own step enables. Both runs end with the same accumulator values, so only the clocking differs.
  3. Switching activity. Icarus Verilog dumps every net to a VCD over a 400 µs window. A second run with SDF back-annotated delays adds the glitches that unit-delay simulation misses.
  4. Power analysis. OpenSTA (LibreLane 3.0.14) reads the routed netlist, the extracted SPEF, the sky130 liberty power models and the VCD; all 4,546 pins get their activity from the simulation. The same is repeated at the typical, fast-cold and slow-cold corners.
  5. Reproducible. audit/power/run_power.sh in the repository rebuilds every number on this page.
This is a pre-silicon estimate of this tile's 1.8 V core only (no pads, Tiny Tapeout multiplexer or other projects). The absolute values depend on the liberty models; the gated/ungated ratio is the robust result. On the bench, the same comparison is one pin: run a workload with uio[4] (test_mode) low, then high with uio[5] low, and compare the core current (≈ 0.15 mA difference expected at 1.8 V).

10. Scan chain

Mux-D scan in RTL. test_mode (uio[4]) forces all row clocks on and puts scan_out on uio[7]; scan_en (uio[5]) is ANDed with test_mode; scan_in is uio[6]. Every flop is on the chain except the two reset-synchronizer flops, which stay off it so reset remains controllable in test mode.

Figure 7 — Chain order from scan_in to scan_out, with the flop count of each field. Every field shifts in LSB first.

Length = 3 + 8 + 8 + 1 + 2 + 8 + 2 + 4 × 16 = 96 flops. The shift test runs through the pins in RTL and on the gate-level netlist; the per-bit map is generated by test/scan_map.py.

12. Host code

Pseudocode for the demo board's microcontroller; set_pins/read_uo stand in for whatever GPIO API the firmware uses (TT MicroPython SDK or C SDK). Strobe timing is in chip clocks: MicroPython is far slower than 4 chip clocks per pin change, but C code writing the GPIO registers directly can toggle in a few ns, so it needs the explicit waits.

A0, A1, B0, B1, CTRL, ROWEN, RSEL = range(7)

def wr(addr, data):
    set_pins(ui=data, addr=addr, strobe=0)
    set_pins(strobe=1)
    wait_chip_clocks(4)     # hold addr/data ≥ 4 chip clocks
    set_pins(strobe=0)
    wait_chip_clocks(2)     # low ≥ 2 chip clocks before the next write

def nib(lo, hi):            # two signed int4 → one byte
    return (lo & 0xF) | (hi & 0xF) << 4

def read_acc(n):            # 32-bit sign-extended accumulator n = COLS*i + j
    v = 0
    for byte in range(4):
        wr(RSEL, byte << 4 | n)
        v |= read_uo() << (8 * byte)
    return v - (1 << 32) if v & 0x80000000 else v

def matmul(A, B):           # A: ROWS×K, B: K×COLS, int4 entries
    wr(CTRL, 0b101)         # clear + auto-step on B1 writes
    for k in range(len(B)): # K up to 511 with 16-bit accumulators
        wr(A0, nib(A[0][k], A[1][k]))                  # column k of A
        wr(B0, nib(B[k][0], B[k][1]))                  # row k of B
        wr(B1, 0)                                      # B1 data unused at 2×2: just steps
    return [[read_acc(COLS*i + j) for j in range(COLS)] for i in range(ROWS)]

For the 2×2 array (ROWS = COLS = 2). Without auto mode, step with wr(CTRL, 0b010) instead of the B1 write. The array size can be read from ID byte 1 (wr(RSEL, 0x81) → 0x22).

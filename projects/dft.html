Error-Detection DFT Architectures

Designed and evaluated multiple fault-detection architectures for 12-nm FinFET benchmark circuits and RISC-V processors, spanning RTL, synthesis, DFT insertion, simulation, equivalence checking, timing analysis, and physical implementation.

This project covered the full path a fault-detection architecture takes from a written specification to a physically implemented block: starting at RTL, moving through logic synthesis and DFT insertion, then verifying correctness in simulation and equivalence checking, and finally closing timing through physical implementation.

The target circuits were a mix of 12-nm FinFET benchmark designs and RISC-V processor blocks, which meant the fault-detection logic had to work correctly across circuits with different structures and timing characteristics rather than being tuned to a single design.

Working across this many stages of the flow — RTL, synthesis, DFT, simulation, equivalence checking, timing analysis, and physical implementation — meant treating each tool's output as an input constraint for the next stage, and re-checking assumptions whenever DFT insertion changed the netlist structure.

Process node12 nm FinFET
Targets12-nm benchmark circuits, RISC-V processors
Flow stagesRTL · Synthesis · DFT insertion · Simulation · Equivalence checking · Timing analysis · Physical implementation
ToolsGenus, Modus, Joules, Xcelium, Conformal, Innovus

Flow

01 / STAGES

  1. RTL

    Writing and reviewing the fault-detection logic at the register-transfer level.

  2. Synthesis (Genus)

    Mapping RTL to gates for each target technology library.

  3. DFT insertion (Modus)

    Inserting scan and test structures into the synthesized netlist.

  4. Power / logic analysis (Joules)

    Checking power and structural impact of the inserted DFT logic.

  5. Simulation (Xcelium)

    Functional verification of the design with DFT structures in place.

  6. Equivalence checking (Conformal)

    Confirming the DFT-inserted netlist is logically equivalent to the original RTL intent.

  7. Physical implementation (Innovus)

    Floorplanning, placement, routing, and timing closure for the final netlist.
